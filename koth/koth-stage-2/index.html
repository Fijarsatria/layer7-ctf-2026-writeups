    KoTH Stage 2 — Glasshouse VM¶

    Field Value
    Event Layer7 CTF 2026 — KoTH
    Stage 2
    Payload 288 bytes
    Cost 1905
    Status VERIFIED

    TL;DR¶

    Stage 2 ("Wraparound Range") changes the VM mask to 0x5A, puts the guest before the host in the arena, and adds READ dst, base, delta. READ checks base < 224 and (base+delta+1) & 0xFF <= 224 but then computes physical = base + delta without masking, so a large delta reaches host memory. The flag is at slot = ((b1*7+b4*3+b6)&3)*48, encrypted with key_i = beacon[(i+2)&7] ^ ((b3^0x6D) + 9*i). A direct 83-byte payload was used for the byte-heavy rounds; for the last two rounds we switched to a 288-byte, gas-oriented prefix/unrolled payload. The best Stage 2 round cost was 1905 at W=1.

    Kit recon¶

    Downloaded glasshouse-kit.zip from the same dashboard button and extracted it to koth/stage-2/. Stage 2 specifics from glasshouse.py:

    • OPCODE_MASK = 0x5A, assembler must be called with --mask 0x5a.
    • GUEST_BASE = 0, HOST_BASE = 256; _finish(..., guest_first=True) builds arena = guest + host, so physical host byte h is at arena index 256+h.
    • New instruction READ (opcode 0x22) is the vulnerable one.
    • Flag encryption: slot = ((beacon[1]*7 + beacon[4]*3 + beacon[6]) & 3) * 48, seed = beacon[3] ^ 0x6D, key_i = beacon[(i+2)&7] ^ ((seed + 9*i) & 0xFF), host[slot+i] = flag[i] ^ key_i. No marker or key is stored in host memory.

    VM analysis¶

    The bug is a truncation mismatch:

    full_end    = registers[base] + registers[delta] + 1
checked_end = full_end & 0xFF
if registers[base] >= 224 or checked_end > 224:
    raise VMError("range outside guest")
physical = GUEST_BASE + registers[base] + registers[delta]
registers[dst] = arena[physical]

    checked_end wraps to a small value while physical stays large. With base = slot + 48 and delta = 208 + i, the check sees checked_end = 1 + slot + i <= 192, but physical = 256 + slot + i, exactly host[slot+i]. The delta register also wraps from 255 to 0 after exactly 48 increments, so it doubles as the loop counter; this removes a separate counter and its SUBI from the hot loop.

    Because 7 == -1 and 3 == -1 (mod 4), the slot can be computed cheaply as (b6 - b1 - b4) & 3, then base = 48 * (s + 1).

    Payload¶

    Two payload families were used:

    • work/stage2/p4.ghb — 83 bytes, gas 744 per run. Direct slot computation, base = slot+48, delta = 208, FETCH/READ-style host read, loop ends when delta wraps. This was used for the byte-heavy rounds (R13-R20, best at W=512..6).
    • work/stage2/gas2_prefix2.ghb — 288 bytes, gas 539 per run. It statically outputs the known Layer7{ prefix and } suffix and decrypts only the 40 middle bytes with an 8-byte-unrolled block. At W=2 and W=1 this wins because gas dominates. Round 24 (W=1) used it for cost 1905.

    Both payloads were locally tested against thousands of random beacons and 48-byte flags covering all four slot values and both unrolled/safe loop paths. The intermediate u2.ghb (108 B, gas 696) was used around W=4..2.

    Result¶

    Stage 2 was solved and scored for all 12 rounds. The platform validated the payloads against all 32 fixed hidden instances. Best observed Stage 2 cost was 1905 at W=1 with the 288-byte prefix/unrolled payload; the smallest valid direct payload was 83 bytes (p4) with gas 744. Stage 3 uses a new FETCH capability bug and is documented separately.
