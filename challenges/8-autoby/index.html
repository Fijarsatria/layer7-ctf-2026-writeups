    TL;DR¶

    Autoby is a 50-stage reversing service. Each stage sends INPUT_BYTES, an ELF_BASE64 checker, and an ANSWER> prompt with a 10-second deadline. The checker applies a reversible 16-byte-block transform and compares the result to an embedded target. Inverting the transform recovers a PNG per stage; the 50 PNGs spell the key. Tesseract misread five glyphs, so the final solver matched glyph shapes against labelled samples.

    Recon¶

    OK 50
Key time limit: 5.000 seconds.
KEY>

    Each stage:

    INPUT_BYTES: 4228
ELF_BASE64: <base64 ELF>
ANSWER>

    The answer for a 4,228-byte input is sent as 8,456 hex characters.

    Analysis¶

    Decoding the first ELF and disassembling it:

    • validator at 0x1880: checks the input length, calls the transform at 0x12c0, compares to target bytes;
    • stage-1 config at file offset 0x2020, target at 0x2048.

    The transform keeps one 32-bit carry and a set of 16-byte blocks. Each round updates blocks in a config-defined order, then mixes each block with its neighbours.

    To invert it:

    1. Recompute the block-update order and key state for every round.
    2. Walk rounds backwards.
    3. Undo the neighbour mixing first.
    4. Undo each block update and restore the previous carry.

    One step has the form:

    y = x + 2x(ax + b)  (mod 2^32)

    The second term is always even, so the lowest bit of x equals the lowest bit of y. Changing a candidate x by 2^k changes the output by 2^k modulo 2^(k+1), so bits can be recovered from LSB to MSB.

    The recovered bytes start with the PNG signature:

    89 50 4e 47 0d 0a 1a 0a

    The first stage image shows the letter f.

    Exploit¶

    After OK 50 the server asks for KEY> with a 5-second limit. The key is one character from each of the 50 PNGs, in stage order.

    Tesseract passed all 50 stages but produced WRONG_KEY; comparing OCR with the images showed five wrong glyphs (b → c, d → c, 9 → 0, 4 → a). One wrong character rejects the whole key.

    The final solver uses shape matching:

    • crop each glyph to its ink bounding box,
    • normalise to 24 × 32 pixels,
    • compare with labelled samples for 0–9 and a–f from earlier sessions,
    • score by pixel difference and aspect ratio,
    • rotate samples by a few degrees to tolerate skew.

    Characters are recognised as each PNG is recovered, so the key is ready the moment KEY> appears.

    Solver: work/8/solve_autoby_glyph.py and the stage artifacts in work/8/.
