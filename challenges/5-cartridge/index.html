    TL;DR¶

    Cartridge ships a stripped static-PIE emu implementing CART-16, a custom 16-bit VM. The emulator exposes hidden I/O ports that map a scratch memory area, plus an ARM/SEAL validation chain before privileged mode 0xC3. Privileged mode validates the write function pointer but executes the read pointer; by rewriting the encoded read pointer (and its 64-bit checksum) through the hidden scratch window, the ROM turns the privileged call into an arbitrary file read and dumps fd 3 (/flag).

    ROM format (from the emulator's banner and analysis):

    "CART" | entry u16 LE | save_size u16 LE | name[8] | bytecode

    The emulator serves a ROM with a 4-byte big-endian length prefix:

    s.sendall(struct.pack(">I", len(rom)) + rom)

    Analysis¶

    Hidden scratch memory¶

    I/O ports 0xFE40 and 0xFE42 expose the emulator's internal scratch memory. The index is obfuscated as:

    offset = 0x8000 + signed16((0xB7E1 * index + 0x4A3D) & 0xFFFF)

    0xB7E1 is invertible modulo 65536, so the mapping can be reversed:

    INV = pow(0xB7E1, -1, 65536)

def scratch_index(offset):
    return ((offset - 0x8000 - 0x4A3D) * INV) & 0xFFFF

    This exposes metadata records: record IDs, nonces, seeds, function pointers, and checksums.

    ARM and SEAL¶

    Two validation stages gate privileged execution.

    • ARM (0xA19E): the ROM scans metadata for a valid UID, writes it to ports 0xFE30/0xFE32, and triggers the request through 0xFE26.
    • SEAL (0x6D17): requires two valid 28-byte packets containing token, nonce, UID, mode, and custom MAC values. The exploit computes them from the runtime metadata instead of hardcoding, so it survives different seeds.

    After both stages the ROM holds the seal needed for privileged mode.

    The bug: pointer check/call mismatch¶

    In privileged mode 0xC3 the emulator validates the write function pointer but the privileged operation ultimately calls the read function pointer.

    The exploit:

    1. Copies the active metadata record into VM memory.
    2. Decodes its protected read function pointer.
    3. Redirects it to the unrestricted read wrapper.
    4. Re-encodes the modified pointer.
    5. Recomputes the record's 64-bit checksum.
    6. Writes the pointer and checksum back into the emulator's scratch memory.

    The validated write pointer is left untouched, so the check passes while the call goes to the unrestricted read.

    Exploit¶

    Privileged read setup:

    Port Purpose
    0xFE20 file descriptor = 3
    0xFE22 destination buffer = 0x40
    0xFE24 read length = 0x80
    0xFE26 execute privileged mode 0xC3
    0xFE00 output console bytes

    First attempt read only 0x40 bytes:

    Layer7{ac1d9bd59be019138f2c00a87c87249f3212a41941b9b8f9401d97628

    The real flag is 72 bytes (7 + 64 hex + }), so the length was raised to 0x80 and the output loop adjusted.

    import socket, struct

host, port = "104.105.149.249", 29651
rom = open("payload.cart", "rb").read()

with socket.create_connection((host, port)) as s:
    s.recv(4096)
    s.sendall(struct.pack(">I", len(rom)) + rom)
    response = bytearray()
    while True:
        data = s.recv(4096)
        if not data:
            break
        response.extend(data)

print(response.decode(errors="replace"))
